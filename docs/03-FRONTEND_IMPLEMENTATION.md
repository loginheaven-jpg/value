# 프런트엔드 구현 가이드

## 1. 기술과 진입점

프런트엔드는 React 19와 TypeScript로 작성되며, Vite가 번들링합니다. 라우팅은 Wouter, 서버 상태는 React Query를 결합한 tRPC 클라이언트, UI는 Tailwind CSS 4와 shadcn/ui 기반 컴포넌트를 사용합니다.

| 파일 | 역할 |
|---|---|
| `client/src/main.tsx` | React 루트, tRPC·React Query Provider 연결 |
| `client/src/App.tsx` | 전체 경로·테마·Toast·오류 경계 연결 |
| `client/src/index.css` | 전역 테마 토큰·기본 스타일 |
| `client/src/pages/*.tsx` | 화면별 여정과 상태 전이 |
| `client/src/components/ValueCard.tsx` | 가치 카드의 공통 표시·클릭 UI |
| `client/src/components/ProgressBar.tsx` | 카드 선택 단계 진행률 |
| `client/src/types/values.ts` | 카드 타입·1~3단계 문구 설정 |
| `client/public/values.json` | 실제 72개 카드 데이터 |

## 2. 브라우저 저장소 계약

다음 키는 화면 간 계약입니다. 이름을 변경하거나 JSON 구조를 바꾸면 관련 모든 페이지와 진행 복원 흐름을 동시에 수정하십시오.

| 저장소 | 키 | 형식·용도 | 주 소유자 |
|---|---|---|---|
| localStorage | `user-name` | 문자열, 사용자 이름 | `Intro.tsx` |
| localStorage | `user-email` | 문자열, 결과 저장·이력 조회 기준 | `Intro.tsx` |
| localStorage | `values-progress` | 1~3단계 진행 상태 JSON, 24시간 만료 | `Sort.tsx` |
| localStorage | `values-step3` | 선택한 5개 `Value[]` | `Sort.tsx` → `PairwiseComparison.tsx` |
| localStorage | `pairwise-progress` | 쌍대비교 인덱스·승리 수 | `PairwiseComparison.tsx` |
| localStorage | `pairwise-results` | 승리 수 기준 정렬된 5개 값 | `PairwiseComparison.tsx` → `FinalSelection.tsx` |
| localStorage | `values-final` | 최종 3개 `Value[]` | `FinalSelection.tsx` → `Result.tsx` |
| sessionStorage | `values-saved-to-db` | 결과 자동 저장 중복 방지 플래그 | `Result.tsx` |
| localStorage | `custom-value-step3` | 과거 Step 3 사용자 정의 가치 정보 | 레거시 |
| localStorage | `custom-value-result` | 결과 화면에서 교체한 사용자 정의 가치 | 레거시 |

### 저장소 수정 원칙

진단을 처음부터 다시 시작할 때는 진행 관련 키만 제거하고 이름·이메일은 유지합니다. 반면 완전히 다른 사용자가 같은 브라우저에서 시작할 수 있는 환경이라면, “다른 사람으로 시작” 기능을 별도로 만들고 `user-name`, `user-email`, 모든 진단 키를 명시적으로 삭제해야 합니다.

## 3. 카드 데이터 계약

```json
{
  "id": 1,
  "korean": "성장",
  "english": "Growth",
  "description": "...",
  "category": "..."
}
```

정식 카드 수는 72개이며, `id`는 1부터 72까지입니다. 카드 id는 브라우저 진행 상태에서 참조되므로 기존 값을 바꾸지 말고, 새 카드를 추가할 때만 새 id를 사용하십시오. 가치 한글명은 현재 결과 DB에 문자열로 저장되므로 명칭 변경은 과거 결과와의 비교·성찰 질문 매핑에 영향을 줄 수 있습니다.

## 4. 핵심 페이지 구현 포인트

### 4.1 `Intro.tsx`

첫 화면은 이름·이메일 입력을 `localStorage`에 저장하고 `/sort`로 이동합니다. 입력 검증은 시작 전에 수행되며, 저장된 이메일이 있으면 이전 결과 보기 동선을 보여줍니다. UI의 3개 특징 카드는 “4단계 여정”이라는 과거 표현을 포함할 수 있으므로, 5단계 프로세스와 문구가 일치하는지 편집 전 확인하십시오.

### 4.2 `Sort.tsx`

카드 선택의 실질적 상태 머신입니다. 카드 목록을 fetch하고, 진행 상태를 복원·저장하며, 1~3단계 후보 집합을 감소시킵니다. 다음 버튼의 핵심 조건은 `selectedIds.size === config.to`입니다. 선택 카드는 상단에 분리되고, 미선택 카드는 하단에 남습니다.

현재 파일에는 제거된 id 73 사용자 정의 카드의 입력 모드와 주석이 남아 있습니다. 데이터 파일에 id 73이 없으므로 해당 분기는 평상시 실행되지 않습니다. 다음 정리 작업에서 사용자 정의 가치 정책을 결정한 뒤 관련 state·함수·조건부 렌더링·storage 키를 함께 제거하거나, 정책에 맞게 재구현하십시오.

### 4.3 `PairwiseComparison.tsx`

선택한 5개의 모든 2개 조합을 비교합니다. 총 비교 횟수는 `5 * 4 / 2 = 10`입니다. 선택된 카드의 승리 수를 누적해 정렬하되, 동률 처리 기준은 코드에서 확인하여 유지하거나 명시적으로 개선해야 합니다. 화면은 진행률을 0/10부터 보여주도록 조정된 이력이 있습니다.

### 4.4 `FinalSelection.tsx`

쌍대비교 순위와 승리 수를 보여주고, 사용자가 최종 3개를 자유롭게 선택하도록 합니다. 알고리즘 순위가 최종 선택을 강제하지 않는다는 제품 원칙을 카피·상호작용에서 유지하십시오.

### 4.5 `Result.tsx`

결과 화면은 저장소·DB·성찰 콘텐츠가 만나는 허브입니다. `REFLECTION_QUESTIONS` 객체는 가치 한글명별 질문을 보유합니다. 새 가치 카드를 추가하거나 명칭을 변경할 때는 이 매핑을 함께 점검하고, 매핑이 없는 가치는 `default` 질문이 노출됨을 인지하십시오.

화면은 결과 진입 시 DB를 자동 저장합니다. 저장 실패 시 세션 플래그를 제거해 재시도할 수 있게 하므로, 오류 메시지를 사용자 친화적으로 개선할 때 이 동작을 훼손하지 마십시오.

### 4.6 `Admin.tsx`

운영자 목록·검색·단일/일괄 삭제 기능을 제공합니다. **현재 접근 제어는 제품 수준에서 완성되지 않았습니다.** UI가 이메일에 따라 링크를 숨기는 것은 서버 권한 통제가 아니므로, 관리자 화면 확장이나 공개 배포 전에 API를 서버 측에서 보호해야 합니다.

## 5. 디자인 시스템의 현재 특성

서비스는 차분한 블루 기반의 밝은 테마와 카드 중심 레이아웃을 사용합니다. 선택·진행·성찰에 집중하도록 화면을 단순화하며, 과도한 장식보다 충분한 여백과 명확한 상태 피드백을 우선합니다.

| 요소 | 현재 원칙 |
|---|---|
| 배경 | `bg-background` 중심의 밝고 안정적인 기본 배경 |
| 주요 강조 | `primary` 토큰으로 선택 카드·진행 상태·CTA 강조 |
| 카드 | 작은 화면 1열에서 큰 화면 최대 4열로 확장 |
| 헤더 | 카드 선택 단계에서 sticky 헤더로 단계·선택 수를 지속 노출 |
| 피드백 | Sonner toast로 로드·복원·입력 오류·저장 상태 안내 |
| 접근성 | 버튼 라벨·키보드 조작을 유지하고 색상만으로 선택 상태를 전달하지 않음 |

색상 값을 페이지마다 하드코딩하기보다 `client/src/index.css`의 CSS 변수와 shadcn/ui 변형을 우선 사용하십시오.

## 6. 프런트엔드 테스트 기준

최소한 아래 시나리오를 매 변경 후 수동 확인하십시오.

| 시나리오 | 기대 결과 |
|---|---|
| 새 사용자 시작 | 이름·유효 이메일 없이 진행 불가 |
| 1단계 | 정확히 20개 선택 전 다음 단계로 이동 불가 |
| 카드 선택 취소 | 선택 카드 영역과 카운트가 즉시 갱신 |
| 새로고침 | 24시간 이내 진행 상태가 올바르게 복원 |
| 3단계 종료 | 5개가 `/step4`에 동일하게 전달 |
| 쌍대비교 | 10회 후 정렬 결과가 `/step5`에 전달 |
| 최종 선택 | 정확히 3개 선택 전 결과로 이동 불가 |
| 결과 진입 | 핵심 가치·성찰 질문·복사 기능 정상, DB 1회 저장 |
| 재시작 | 이름·이메일 유지, 진단 상태 제거 |
| 모바일 | 카드·고정 버튼·텍스트가 화면 밖으로 넘치지 않음 |
