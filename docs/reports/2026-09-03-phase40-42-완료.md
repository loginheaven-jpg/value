## 3. 지시서 대비 이탈과 사유

### ① `StepConfig` 에 `mode`·`min`·`max` 를 넣지 않았다

원본 §3.7 과 v3.1 C-1-5 가 지시했으나 넣지 않았다. v3.2 아래에서 **독자가 하나도 생기지 않기
때문이다** — D-3 게이트는 모듈 상수(`TRIAGE_FLOOR`·`CEIL`·`MAX_ROUND`)를 읽고, D-2 가 mode 기반
진행바 분기를 폐기했으며, D-5 는 `Sort` 의 분기를 `currentStep` 으로 못박았다. 넣으면 하한
값의 진실이 둘(모듈 상수와 `config.min`)이 된다. `barLabel` 만 추가하고 `to` 는 건드리지 않았다.

### ② 인쇄 — CSS 만이 아니라 렌더 구조를 바꿨다

§5.2 는 `index.css` 에 `@media print` 를 넣는 것으로 끝내라 하지만, §9 Phase 41 의 수용 기준은
'인쇄 미리보기에서 성찰 질문이 모두 펼쳐진다' 이다. 성찰 질문이 `{isExpanded && (...)}`
조건부 렌더라 **접힌 카드의 질문은 DOM 에 없다.** 미디어 쿼리는 없는 노드를 펼치지 못한다.
처방과 기준이 양립 불가였다.

기준을 살리고 처방을 고쳤다. 블록을 항상 렌더하고 접힘을 클래스로만 표현한다. 인쇄 버튼
`onClick` 에서 펼치는 대안은 채택하지 않았다 — D-7 이 인쇄 버튼을 767px 이하에서 감추므로
모바일에서 브라우저 메뉴로 인쇄하면 기준이 다시 깨진다. CSS 경로는 두 진입점을 모두 덮는다.

### ③ 24장 상한을 보충 화면 출구에도 적용했다 (F-3)

D-3-4 는 보충 화면 통과 조건을 '선택 수 ≥ need, 상한 없음' 으로 두었다. 그러면 `yes=11` 인
참여자가 보충에서 40장을 골라 51장으로 통과하는 반면, `yes=30` 인 참여자는 재분류로
되돌려진다. **같은 51장이 경로에 따라 통과하기도 하고 막히기도 한다.**

검토 화면의 출구도 같은 `resolveTriageOutcome` 을 **같은 라운드로** 통과시켜 두 경로를
일치시켰다. 아울러 재분류를 강제가 아닌 **권유**로 만들었다("한 번 더 나누기" / "이대로
진행하기"). 문구가 "나눠 볼까요?"라고 묻는 이상 거절할 수 있어야 하고, 거절해도 하한은 이미
넘긴 상태라 2단계는 안전하다.

게이트가 보장하는 불변식은 하나로 유지된다 — **`proceed` 는 언제나 '네' 12장 이상**.
전 조합(yes 0~72 × maybe × round 1~4)으로 테스트한다.

### ④ Phase 40-B 를 Phase 40 에 합쳤다

D-10 은 40-B 를 P2 로 분리했으나, 무작위 셔플을 먼저 넣고 곧바로 걷어내는 것이 되므로
`buildTriageQueue` 를 처음부터 결정론으로 만들었다. 결과적으로 RNG 가 코드에 들어온 적이 없다.

### ⑤ 지시서가 지목하지 않은 문서까지 고쳤다 (G-10)

Phase 42 기준은 `docs/02`·`03`·`07` 만 지목하지만 '20개 선택' 사양은 `docs/00` §4.2,
`docs/05` §6, `README.md` 에도 남아 있었다. `docs/05` §6 은 서술이 아니라 **실행되는 QA
체크리스트**라 그대로 두면 Phase 40 이후 가짜 회귀를 만든다.

### ⑥ 전이를 순수 함수로 분리했다 (G-3)

원본 §9 Phase 40 의 회귀 기준 2건('72장 완주 후 후보군이 yes 더미와 일치'·'되돌리기가 직전
판단을 정확히 취소')이 C-9 → D-9 개정 과정에서 승계되지 않았다. 기준을 되살리려면 전이가
컴포넌트 밖에 있어야 한다. `jsdom`·`testing-library` 를 새로 들이는 대신
`decideCard`·`undoDecision`·`startRerun` 을 꺼냈다. `Sort` 의 핸들러는 `setState` 를 뺀 나머지가
