# 미개발 기능·알려진 이슈·권장 로드맵

## 1. 우선순위 원칙

다음 작업은 사용자 정보 보호와 데이터 정합성을 우선합니다. UI 카피·시각 개선은 중요하지만, 관리자 API 공개·이메일 기반 결과 노출 같은 보안 이슈를 해결한 뒤 진행하는 것이 안전합니다.

## 2. 즉시 결정·정리할 항목

### 2.1 사용자 정의 가치 기능의 제품 정책 (결정됨 — Phase 39-C)

지휘부 결정: **결과 화면의 가치 교체는 유지하고, 1단계의 73번 카드 경로는 제거한다.**

근거는 §7.2다. 1단계를 분류로 바꾸면 "내 가치가 목록에 없다"는 불만은 줄지만 사라지지는 않는다.
진단의 마지막 지점에서 참여자에게 최종 권한을 남기는 것은 `docs/07`의 '자율성' 원칙과 맞는다.

| 항목 | 결정 | 상태 |
|---|---|---|
| 정식 카드 수 | 72개로 고정 | 유지 |
| `Sort.tsx`의 id 73·커스텀 입력 레거시 | **제거** | Phase 39-C 완료 |
| `custom-value-step3` 저장소 키 | **폐기** (쓰기·읽기 모두) | Phase 39-C 완료 |
| `Result.tsx`의 "나만의 가치 추가하기" | **유지** | 변경 없음 |
| `custom-value-result` 저장소 키 | **유지** | 변경 없음 |
| `values_assessments.customValue` 컬럼 | **유지** | 마이그레이션 없음 |

`customValue`에 값이 들어오는 경로는 이제 하나다 — 결과 화면의 교체. 이전에는 두 경로(1단계 추가·결과
교체)가 같은 컬럼을 채워 데이터 의미가 섞였다. 그 혼재가 해소됐다.

### 2.2 관리자 API 권한 보호

| 위험 | 상태 | 조치 |
|---|---|---|
| 전체 결과 조회 | **해소** (Phase 39-A) | `values.getAll` → `adminProcedure` |
| 단일·일괄 삭제 | **해소** (Phase 39-A) | `delete`·`deleteMany` → `adminProcedure`. 감사 로그는 미구현 |
| `/admin` 화면 | **해소** (Phase 39-A) | 가드가 하나도 없었다. `auth.me` 기반 로그인·권한 게이트 추가 |
| 결과 이력 조회 | **미해소** | `getByEmail`은 참여자가 세션 없이 부른다. 소유권 검증 방식은 §6.1 결정 사안. 완화로 이메일 컬럼 반환을 제거 |
| 결과 저장 | **미해소** | `values.save`가 미인증 쓰기다. 잠그면 앱이 죽는다. §6.1과 함께 다뤄야 한다 |

## 5. 권장 실행 순서

### 1단계: 안전한 운영 기반

서버 관리자 권한, 결과 소유권 보호, 개인정보 안내를 먼저 구현합니다. 구현 후 실제 운영 DB 권한, 네트워크, 감사 로그를 점검합니다.

### 2단계: 데이터·기능 정합성

사용자 정의 가치 기능의 유지 여부를 제품 담당자와 결정합니다. 유지한다면 72개 표준 카드와 사용자가 쓴 보완 가치를 구분해 저장·표시하는 모델을 설계하고, 제거한다면 레거시 코드·DB 컬럼·UI를 단계적으로 없앱니다.

### 3단계: 안정성·검증

진단 단계 전이와 결과 저장에 단위 테스트·통합 테스트를 추가합니다. 특히 72개 카드, 10개 쌍대비교, 3개 최종 선택, 중복 저장 방지, 재시작 흐름을 자동화합니다.

### 4단계: 사용자 가치 확장

이메일 결과 발송, PDF, 워크숍 모드, 비식별 분석을 개인정보·권한 설계와 함께 추가합니다.

## 6. 작업 규칙

새 기능 또는 버그 보고를 받으면 다음 순서를 따릅니다.

1. `todo.md`에 검증 가능한 미완료 항목을 추가한다.

## Phase 41 — 인쇄

`@media print` 만으로는 수용 기준을 채울 수 없었다. 성찰 질문 블록이 `{isExpanded && (...)}`
조건부 렌더여서 접힌 카드의 질문은 CSS 로 숨겨진 것이 아니라 **DOM 에 없었다**. 미디어 쿼리는
없는 노드를 펼치지 못한다. 지시서 §5.2 의 처방(CSS만 추가)과 §9 Phase 41 의 기준(인쇄
미리보기에서 성찰 질문이 모두 펼쳐진다)이 양립하지 않는 상태였다.

기준을 살리고 처방을 고쳤다 — 블록을 항상 렌더하고 접힘을 클래스로만 표현한 뒤, 인쇄에서
그 숨김을 해제한다. 인쇄 버튼 `onClick` 에서 펼치는 방법도 있었으나 채택하지 않았다. D-7 이
인쇄 버튼을 767px 이하에서 감추므로, 모바일에서 브라우저 메뉴로 인쇄하면 기준이 다시
깨진다. CSS 경로는 두 진입점을 모두 덮는다.

되돌아가기 쉬운 결합이라 테스트로 잠갔다(`client/src/pages/resultPrint.test.ts`). 조건부
렌더로 복귀하거나 `!important` 를 빼면 실패한다 — 둘 다 음성 대조로 확인했다.

### TiDB 노출 — 조치 순서 정정

앞선 보고의 "실제 조치는 비밀번호 교체"는 절반만 맞았다. `20c77b9` 의 두 JSON 을 실측하면

않았다.** 전체 히스토리에 `mysql://user:pass@` 형태도 없고(유일 매치는 자리표시자),
`JWT_SECRET`·`OWNER_OPEN_ID`·`FORGE_API_KEY` 도 전부 자리표시자다. 참여자 데이터도 없다.

| 순서 | 조치 | 사유 |
|---|---|---|
| 1 | **TiDB 접근 제어 확인** | 공개 엔드포인트인지, IP 허용목록이 있는지. 사용자명이 알려진 상태에서 무제한 접속이 열려 있으면 그것이 실제 위험이다 |
| 2 | 해당 사용자 비밀번호 교체 | 잔여 위험 제거. 급하지 않다 |
| 3 | 히스토리 재작성 | force-push 부작용을 따진 뒤. 이미 공개된 값이라 되돌려도 회수되지 않는다 |

같은 파일에 **`DELETE FROM values_assessments;` 를 운영 DB 에 실행한 기록**이 남아 있다.
자격증명과 별개로 운영 이력이 공개돼 있다는 사실 자체를 사안으로 취급한다.
