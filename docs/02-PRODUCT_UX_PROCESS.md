# 제품·UX·진단 프로세스 설계

## 1. 제품 목적

이 서비스는 사용자가 자신의 삶을 이끄는 핵심 가치를 발견하고, 결과를 성찰과 의사결정에 활용하도록 돕는 디지털 진단 도구입니다. 진단은 객관적인 심리검사 점수를 산출하거나 사람을 평가·분류하지 않습니다. 대신 카드 선택, 쌍대비교, 최종 자유 선택을 통해 사용자의 직관과 언어화를 돕습니다.

## 2. 경험 설계 원칙

| 원칙 | 적용 방식 | 금지할 패턴 |
|---|---|---|
| 직관 우선 | “마음이 더 끌리는”, “가슴이 이끄는 대로”라는 카피 | 정답·우열·사회적 기준을 암시하는 표현 |
| 점진적 축소 | 72→20→10→5→3으로 인지 부담을 나눔 | 처음부터 소수의 가치를 고르게 하기 |
| 선택의 회복 가능성 | 선택 카드 분리, 다시 클릭 해제, 이전 단계 이동 | 실수 후 처음부터 다시 시작하게 하기 |
| 우선순위의 보조성 | 쌍대비교 순위는 참고용, 최종 3개는 자유 선택 | 알고리즘 결과를 절대적 정답처럼 제시 |
| 성찰로의 연결 | 최종 가치별 질문과 활용 방법 제공 | 결과를 단순 명사 목록으로 종료 |
| 안정감 | 자동 저장, 남은 선택 수, 진행률 표시 | 사용자가 현재 위치·저장 여부를 알 수 없게 하기 |

## 3. 전체 사용자 여정

```text
소개와 신뢰 형성
  → 개인 정보 최소 입력
  → 넓은 직관적 선택
  → 더 깊은 자기 동일시
  → 타협 불가 가치 추출
  → 쌍대비교로 우선순위 관찰
  → 자유로운 최종 선언
  → 성찰·기록·재방문
```

### 3.1 첫 화면

첫 화면은 서비스의 목적과 부담 없는 시작을 전달합니다. 사용자는 이름과 이메일을 입력한 뒤 진단을 시작하며, 이메일을 입력한 경우 이전 결과 보기로도 이동할 수 있습니다. 현재 카피는 “72개의 가치 카드를 천천히 **좁혀가며**, 진짜 나를 발견하는 여정”이라는 방향을 사용합니다.

이메일은 이력 조회 및 결과 저장의 키로 사용되므로, 화면에는 수집 목적과 보관 범위를 명확히 알리는 개인정보 안내와 동의 절차를 추가하는 것이 바람직합니다.

### 3.2 1~3단계 카드 선택

| 단계 | 후보 수 | 선택 수 | 지시문 의도 |
|---|---:|---:|---|
| 1단계 | 72 | 20 | “마음이 더 끌리는” 가치를 고르게 하여 당위적 판단을 낮춤 |
| 2단계 | 20 | 10 | “이것 없이는 정말 나답지 않아”라는 자기 동일시를 촉진 |
| 3단계 | 10 | 5 | 삶에서 “절대 타협할 수 없는” 핵심을 추출 |

선택한 카드는 상단의 강조 영역으로 이동하고, 선택하지 않은 카드는 하단에 남습니다. 상단 영역은 사용자가 현재 선택을 계속 관찰하고 바로 해제할 수 있게 만드는 핵심 UX입니다. 데스크톱에서는 최대 4열, 작은 화면에서는 1~2열로 반응합니다.

### 3.3 4단계: 쌍대비교

5개 카드에서는 모든 두 카드 조합, 즉 10번의 비교가 진행됩니다. 각 비교에서 사용자는 “두 가지 중 하나를 선택한다면?”이라는 질문에 직관적으로 더 중요한 하나를 고릅니다. 각 카드의 승리 수로 정렬 순위를 계산하지만, 이 결과는 다음 단계의 **참고 정보**입니다.

쌍대비교의 역할은 사용자가 미세한 우선순위를 관찰하게 하는 것이지, 가치의 객관적 서열을 확정하는 것이 아닙니다. 따라서 “정답은 없습니다”라는 안내와 최종 자유 선택을 유지해야 합니다.

### 3.4 5단계: 최종 3개 선택

사용자는 정렬된 5개를 보고 “당신의 인생을 대표할 3가지”를 선택합니다. 순위 아이콘과 승리 수는 인지 보조물이며, 사용자는 1~3위에 구속되지 않고 어떤 3개든 선택할 수 있습니다.

### 3.5 결과·성찰

결과 화면은 축하 메시지와 함께 가치 3개를 보여주며, 각 카드의 성찰 질문을 펼쳐볼 수 있습니다. 사용자는 결과를 클립보드로 복사하고, 이메일 기준의 과거 결과를 조회하거나 다시 진단할 수 있습니다. “다시 시작”은 이름·이메일을 유지하면서 진단 상태만 지우도록 설계되어 있습니다.

## 4. 화면별 기능 명세

| 화면 | 핵심 요소 | 상태·예외 처리 |
|---|---|---|
| Intro | 브랜드, 3개 특징 카드, 이름·이메일, 시작 버튼 | 입력 누락·이메일 형식 오류 안내, 이전 결과 링크 |
| Sort | Sticky 헤더, 진행률, 선택 수, 선택/미선택 카드 영역, 이전/다음 버튼 | 24시간 내 저장 진행 복원, 정확한 선택 수가 되기 전 다음 비활성 |
| Pairwise | 비교 진행률, 양쪽 카드, 이전 이동 | 10개 조합 생성, 비교 진행 상태 저장 |
| FinalSelection | 순위·승리 수, 최종 선택 수, 결과 이동 | 정확히 3개 선택해야 진행 |
| Result | 축하 문구, 가치 카드, 성찰 질문, 복사·이력·홈·재시작 | `values-final` 미존재 시 홈으로 이동, DB 저장 오류는 재시도 가능 |
| MyResults | 이전 진단 목록, 상세 펼치기, 새 진단 | 이메일 없음 또는 결과 없음 안내 |
| Admin | 전체 목록, 검색·필터, 삭제 | **현재 서버 권한 검증 없음—운영 전 보완 필요** |

## 5. 카피 변경 원칙

카피를 수정할 때는 “선택해 주세요” 같은 명확한 행동 지시와, 사용자의 자기 탐색을 지지하는 정서적 언어를 균형 있게 사용합니다. 단정적 진단, 의학적 효능, 타인 비교, 성공을 보장하는 표현은 사용하지 않습니다.

| 목적 | 권장 표현 | 피해야 할 표현 |
|---|---|---|
| 직관 유도 | “마음이 더 끌리는”, “가슴이 이끄는 대로” | “가장 옳은”, “객관적으로 우수한” |
| 가치 명료화 | “나답지 않다”, “삶을 대표하는” | “성공을 보장하는” |
| 결과 해석 | “당신을 위한 나침반”, “성찰의 출발점” | “당신의 성격을 확정한다” |
| 재진단 | “가치의 변화를 돌아보기” | “이전 결과가 틀렸다” |

## 6. 분석·콘텐츠 확장 시 주의사항

현재 결과 DB에는 최종 가치 3개만 저장됩니다. 향후 다음 기능을 만들려면 별도 데이터 설계가 필요합니다.

| 확장 기능 | 추가로 저장할 데이터 | 설계 유의사항 |
|---|---|---|
| 가치 변화 추이 | 진단 버전, 카드 세트 버전, 단계별 선택·비교 결과 | 카드 삭제·명칭 변경에도 과거 결과를 해석할 수 있게 버전 보관 |
| 집단 워크숍 | 워크숍 id, 참여 동의, 집계 단위 | 개인 식별 정보와 집계 데이터를 분리 |
| PDF 리포트 | 생성 시점, 리포트 스냅샷, 파일 키 | 개인정보 포함 여부·접근 권한·보존 기간을 설계 |
| 추천 성찰 콘텐츠 | 가치별 콘텐츠 버전·노출 이력 | “추천”을 진단·치료로 표현하지 않음 |
